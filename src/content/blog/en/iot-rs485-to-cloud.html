A lubrication skid on a factory floor and a charger on a parking deck do not fail like a mobile app. They fail like physics: common-mode noise on a long pair, a transceiver that latches, a night-shift outage that lasts longer than RAM. If the cloud never sees the packet, billing is wrong, a machine runs dry, or a session never closes.

This article is a field guide for the path from differential serial and OCPP 1.6 to a cloud ingestion API — without pretending an MQTT tutorial is an industrial system. Edge nodes are unreliable publishers. The bus is a hostile analog environment. The backend is an idempotent ledger, not a firehose of unique snowflakes. That distinction drives most of the trade-offs below.

What this is not. It is not a schematic for a hobby ESP32 weather station. If your link is USB on a lab bench and your “backend” is a JSON file, a well-bounded script is cheaper. The architecture here exists because EMI, brownouts, and simultaneous reconnect storms are the default, not the incident.

The lost-packet failure mode

The symptoms are boring and expensive:

  • CRC theater. Frames are parsed, checksums are optional, and a flipped bit becomes a plausible temperature.
  • RAM as a buffer. The gateway stores unsynced telemetry in volatile memory. Power blips; the shift’s data never existed.
  • Naive reconnect. The plant network returns. Two hundred nodes retry in the same millisecond. The ingestion service is the outage.
  • Non-idempotent POSTs. Replay after a timeout double-counts volume, energy, or lubrication cycles. Finance notices before engineering does.

I learned this first on Smart Lub for Vulcano Lubricación — an RS485 telemetry device that had to survive a factory, then a commercial catalog. I learned it again on OCPP 1.6-J charge points, where a dropped WebSocket is a metering and remote-command problem, not a spinner on a phone.

Three principles that survive the floor

Everything else is an implementation detail of three rules.

  1. Believe the physical layer. Differential signaling rejects common-mode noise; it does not invent integrity. CRC (or protocol checksum) on every frame, timeouts that reset stuck UARTs, a hardware watchdog that loves nobody.
  2. Durability before elegance. Unsynced frames live in EEPROM, flash, or an industrial SD with a wear plan. RAM is a cache, not a log.
  3. Replay is the happy path. Sequence IDs, idempotent upserts, and jittered backoff. The cloud must assume every packet will arrive twice, late, or in a burst after a blackout.

The layered system

Name the layers so a firmware engineer and a backend engineer can argue about the same boxes.

Physical and link

RS485 is a differential pair with polarity, termination, and bias that will be wired wrong on site. OCPP 1.6-J is JSON over a persistent TLS WebSocket with a state machine that does not care about your REST habits. Both are links that drop. Neither is “HTTP with extra headers.”

Edge gateway

Microcontroller or small Linux box: decode, verify, buffer, publish. On Smart Lub that meant CRC-checked Modbus-style frames, Ethernet or Wi-Fi as the northbound path, and local storage so a shop-floor switch reboot was not a data-loss event. On chargers that meant keeping the OCPP session honest while metering ticks continued locally.

Ingestion and product

Cloud Run (or equivalent), a PostgreSQL-shaped truth, and a Flutter or web ops surface. The API’s primary job is deduplication. Visualization is a privilege you earn after the ledger is boring.

Southbound commands — remote stop, firmware nudge, start transaction — need their own timeouts and acknowledgements. A stuck HTTP handler must not stall the UART ISR. Architecture tests here are integration tests with a killed NIC, not mocks that always succeed.

Respect noise, parity, and stuck silicon

Factory floors and outdoor charge bays are EMI generators with a parking lot attached. Differential RS485 helps. Firmware still has to:

  • Compute CRC16 (or the protocol’s checksum) on every frame and drop failures without “best effort decode.”
  • Bound reads with hardware timeouts so a missing stop bit cannot hang the main loop.
  • Pet a watchdog that resets a wedged transceiver instead of waiting for a truck roll.

OCPP is not analog noise, but it rhymes: malformed JSON, half-open TCP, and a charge point that thinks it is still in a transaction. Treat schema validation like CRC. Treat idle timeouts like UART framing timeouts.

Ack only after durability on both sides. Clearing a local buffer because the TCP write returned is how you lose the blackout window. The sequence ID is cleared when the ingest API reports a committed upsert — or when a later reconcile job says the cloud already has it.

Intermittent connectivity is the operating mode

On phones, a drop is a spinner. On a lubrication line or a charger, a drop is missed billing or a dry bearing. Design for the partition:

  • Local buffering. Circular log in EEPROM or flash with a high-water mark and a strategy for when the log is full (drop oldest vs fail closed — a product decision, not a silent wrap).
  • Idempotent ingestion. Unique deviceId + sequenceId (and for OCPP, transaction and meter-value identities the spec already gives you). Replays merge; they do not append a second universe.
  • Backoff with jitter. A site-wide power restoration is a thundering herd with Ethernet cables. Exponential backoff without jitter is a synchronized self-DoS.

OCPP 1.6 is the same architecture in a suit

A CSMS holding persistent WSS connections to charge points is Smart Lub’s Ethernet publisher with a larger state machine. Meter values are telemetry frames. RemoteStartTransaction is a southbound command with a deadline. Billing reconciliation is the idempotent ledger with legal consequences.

The Flutter dashboard is not the system. It is a subscriber of committed state. If the UI is live and the ingest path is not durable, you have built a demo that lies quickly.

Edge log plus idempotent API

  • Blackouts become delay, not loss.
  • Backend retries are safe by construction.
  • Ops can explain gaps as “not yet acked,” not “maybe gone.”
  • The same pattern ports from Modbus to OCPP without a new religion.

The infinite buffer fantasy

  • Flash wears. EEPROM fills. You need a drop policy.
  • Clock drift makes “event time” a debate unless devices have a sync story.
  • Exactly-once delivery is a myth; exactly-once effects are an upsert key.
  • Southbound commands during a partition need an operator-visible pending state.

Industry writing on IoT often stops at “use MQTT and QoS 1.” That is how you get a distributed pile of unique messages and a database full of twins. A sequence space, a durable log, and an upsert are the minimum adult supervision.

The full-stack advantage, without the mystique

Knowing why a MAX485 needs termination does not make you a better React developer in the abstract. It makes you refuse APIs that cannot replay, UIs that treat “connected” as “true,” and firmware that blocks on HTTP in the receive path. The register-level instinct is a bias toward bounded work and explicit failure.

Pros and cons, without the slideware

Dimension What you gain What you pay
Integrity Corrupt frames die at the edge. The ledger sees verified facts. You drop data you cannot prove. Counters and alarms must show the drop.
Availability Sensing continues through a dead WAN. Replay closes the gap. Local storage, wear, and a reconcile job that someone has to own.
Cloud Horizontal ingest that assumes duplicates. Billing math stays explainable. Schema and sequence contracts are forever. Changing them is a fleet problem.
Operations Dashboards reflect committed state; technicians debug acks, not vibes. You will still roll a truck for polarity, termination, and a wet RJ45.
Transfer RS485 lessons transfer to OCPP, and back, because the failure modes rhyme. Teams will over-abstract “the IoT platform” and ship a gateway that does nothing well.

When not to do this

  • Lab-only links. If the device never leaves a bench and the data is not money or metal, a Python script and a CSV is honest.
  • No sequence space. If you cannot name a unique event, you cannot upsert. Do not paper over that with “Kafka will sort it out.”
  • Cloud-first firmware. If the sample loop waits on HTTPS, you have coupled physics to someone else’s SLO.
  • A dashboard as source of truth. Live WebSockets that bypass the ledger will disagree with invoices. Pick one source; make it the database.

Closing

Industrial telemetry is an operating system for partitions, wearing a serial cable. CRC, non-volatile logs, jittered replay, and idempotent upserts are how you keep a factory or a charge network from inventing data. They are also how you inherit a new class of work: flash wear, sequence epochs, and a platform team that must treat the edge like a kernel.

Use the shape when loss is a safety or billing event. Skip it when you are still one sensor on a desk. And never confuse a connected dashboard with a durable system — the wire still gets noisy, the power still drops, and the cloud still has to survive being told the same truth twice.
